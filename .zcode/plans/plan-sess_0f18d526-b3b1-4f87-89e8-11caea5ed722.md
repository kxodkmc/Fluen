# 「双栏」→「半预览」改造方案（修订版：稳定性·安全性·可拓展性强化）

## 一、架构决策（为什么这样做最稳定）

| 方案 | 结论 |
|---|---|
| Milkdown/Tiptap 等独立 WYSIWYG 引擎 | ❌ 引入 ProseMirror 全家桶；Markdown 往返转换会改写用户原文（自定义 f- 标签、脚注、sec-id 标记丢失）；撤销历史分裂；与「体验和代码视图同步」直接冲突 |
| **CM6 实时渲染装饰扩展（选定）** | ✅ Obsidian Live Preview 同款架构。同一 EditorView/同一文档/同一撤销栈，装饰只改视觉层、**文档文本永不被改动**——dirty 判断、Ctrl+S 保存、大纲联动、doc-change→预览链路全部零改动自动生效 |

## 二、模块化设计（依赖单向：plugin → 其他；无循环；每文件 < 400 行）

新目录 `src/views/main/components/editor/codemirror/livePreview/`：

```
state.ts        开关状态：StateEffect<boolean> + StateField（默认关）。
                模式切换 = dispatch 一个 effect，绝不 setState() → 光标、撤销历史、
                选区全保留，切换瞬时完成。
mathSyntax.ts   $...$/ $$...$$ 语法节点扩展（MarkdownConfig + InlineParser +
                BlockParser）。完全复刻 footnoteSyntax.ts 已验证的模式：字符级
                线性扫描（非正则）、树外按需提取、import.meta.vitest 内嵌测试块。
widgets.ts      WidgetType 定义：KaTeX 公式 widget、列表圆点 widget。
                只接收调用方传入的纯数据，不触碰编辑器状态。
decorations.ts  纯函数核心：(doc, tree, selection) → Decoration 区间集合，
                【规则注册表】结构——每种 markdown 元素一条独立 handler，
                未来扩展（如图片渲染）只需追加一条规则。
plugin.ts       ViewPlugin 接线层：可视区计算、composing 守卫、atomicRanges、

index.ts        barrel 导出 livePreviewExtension 与开关辅助函数。
```

## 三、稳定性保障（必须项，逐条落实）

1. **文档不可变原则**：所有效果通过 Decoration（mark/line/replace/widget）实现，`doc.toString()` 永远不变 → 保存链路与双栏时代的代码路径完全一致，不可能产生回归。
2. **切换零损耗**：StateEffect 开关，不重建 EditorState，撤销历史/光标/滚动位置全保留。
3. **IME 安全**：`update.viewComposing === true` 时跳过装饰重建，中文输入法组词期间视图完全静止（Obsidian 中文社区踩过的坑，直接规避）。
4. **光标安全**：所有 replace/widget 区间注册到 `EditorView.atomicRanges`，光标无法进入零宽隐藏区造成"卡死/跳字"。
5. **性能**：基于 `view.visibleRanges` ∪ 光标所在段落计算，大文档 O(视口)；树未变（`update.treeChanged===false` 且视口未变）时复用上次结果。RangeSet 区间按序插入保证合法性。
6. **故障隔离降级**：每条装饰规则独立 try/catch，某条规则抛错仅降级为该段显示原始 markdown，编辑器整体永不白屏崩溃；KaTeX 渲染 try/catch + throwOnError:false 双保险，失败回退原文。
7. **依赖归位**：`@lezer/markdown`、`@lezer/common` 由 devDependencies 移至 dependencies（现有生产代码已在静态导入它们，属修正声明，无新增包、无版本变化）。

## 四、安全边界（必须项）

1. **链接点击**：解析出 URL 后仅当 scheme ∈ {http, https, mailto} 才经 `@tauri-apps/plugin-opener` 打开，杜绝 `javascript:`/`file:`/`data:` 注入。
2. **DOM 属性注入**：link mark 的 `data-href`、hover title 均经 HTML 转义后写入。
3. **KaTeX 安全配置**：使用默认 `trust: false`（禁用 \href、\includegraphics 等），渲染产物只进入公式 widget 的受限容器；这是学术平台防 TeX 注入的正确姿势，与文献阅读器管线的处理方式一致。
4. **防正则灾难回溯**：数学语法用字符线性扫描（同 footnote 实现），永不写贪婪嵌套正则。
5. **新增安全测试用例**：恶意构造 `$<img src=x onerror>...$` 等 TeX/HTML payload，断言输出 DOM 不含可执行元素。

## 六、测试与验收

- 每个 livePreview 文件内嵌 `import.meta.vitest` 测试块（与 footnoteSyntax 相同守卫模式）：语法识别正确性、装饰区间快照、光标揭示行为、atomicRanges 完整性、安全 payload、切换开关效果。
- `pnpm test` 全量回归（现有 formatting/ftag/footnote/table 测试必须全绿）+ `vue-tsc --noEmit`。
- 手动验收清单：三视图切换（撤销历史保留）、中文 IME 连续输入、行内/块级公式、链接点击 scheme 校验、Ctrl+S 保存归一化回写后半预览仍正常。
