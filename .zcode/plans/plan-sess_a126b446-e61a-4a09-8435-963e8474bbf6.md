# 审批 diff 展示 + 写前必读门禁 实施方案

## 目标（对应三条需求）
1. 审批确认框展示**真实行级 diff**（删除标红、新增标绿），采用「卡片摘要 + 全屏 hunk 视图」新形态：卡片只显示 `+N/−M` 统计与「查看变更」按钮，全屏视图**只渲染变更块**，未改动的大段论文文本折叠为「… N 行未变 …」，永不整篇铺开。
2. 工具 description 中明确：已有文件的局部修改禁止用 `project_write`，必须走 `project_edit`。
3. 强制 read-before-write 门（edit + write 覆盖 + manuscript 全覆盖）：未先用 `project_read` 完整读取原文（窗口覆盖全文、且文件未变更）的写操作，**在弹出审批框之前**即被拒绝，错误反馈给模型促其先读。

## 后端（src-tauri，不改 crates/ 子仓库）

### A. 读取状态跟踪器 `agent_tools/project/read_state.rs`（新）
- `ReadTracker = Arc<Mutex<HashMap<PathBuf, FileReadRecord>>>`；记录含：已读字符区间列表（合并后）、`total_chars`、指纹（mtime + 字节数）。
- `record_read(path, offset, end, total_chars, fingerprint)`：由 `project_read` 成功后调用（解析 referee 输出 JSON 的 offset/end/total_chars 字段）。
- `is_fully_read(path)`：指纹与当前文件一致 且 区间并集覆盖 `[0, total_chars)` 才为 true；文件变动即失效。
- `record_full(path, fingerprint)`：我方 write/edit 成功后登记（模型对刚写入的内容有完整认知，避免强制重读死循环）。
- 实例挂在 `MotisChatState`（managed 长生命周期，学术助手已复用其 approvals 通道，加 `read_tracker_handle()` 同构共享）。

### B. 读门装饰器 `agent_tools/project/read_gate.rs`（新）
- `ReadGateGuard` 镜像 `ApprovalGuard` 的透传壳结构（agent_runtime/approval.rs:88-118 模式），包住写工具本体。
- execute 前置检查：按工具名取目标（`project_edit`/`project_write` → args.path；`manuscript` → `manuscript/main.md`）；目标不存在（新建）放行；存在且未完整读取 → 返回 `ToolError::Execution("请先用 project_read 完整读取…")`，**不进审批弹窗**。
- 内层成功后 stat 新文件并 `record_full` 刷新指纹。
- 装配顺序：`ApprovalGuard(ReadGateGuard(tool))`（assemble.rs 中 `register_manuscript` / `register_project_files` 调整，read/write/edit/manuscript 构造器加 `Option<Arc<ReadTracker>>` 参数；调用点 motis_chat/runtime.rs、agents.rs、ai_assistant/runtime.rs 同步传 `chat_state.read_tracker_handle()`）。

### C. 审批 payload 附带 diff `motis_chat/approval_diff.rs`（新）
- 依赖：`src-tauri/Cargo.toml` 加 `similar = "2"`（行级 diff，全仓现无 diff 库）。
- 纯函数 `build_approval_diff(project_root, tool_name, input) -> Option<ApprovalDiff>`：
  - 读当前文件原文（不存在则视为空）；推演新内容：`project_edit` 按 referee 同规则 replacen（old_string 不唯一/不存在 → 放弃 diff 返回 None），`project_write`/`manuscript` 用 input.content。
  - `TextDiff::from_lines` + `grouped_ops(3)` → `hunks: [{ gap_before, lines: [{ kind: ctx|add|del, text }] }]`，附 `added/removed` 统计与行数上限截断标志（防极端全文件重写撑爆 payload）。
- `MotisApprover::new` 增加 `project_path: Option<String>`（两个构造点 commands.rs:178 / ai_assistant commands.rs:154 均有该值）；approve() 发事件前算好 diff。
- `ApprovalRequestPayload`（events.rs:123-131）加 `diff: Option<ApprovalDiff>`（`skip_serializing_if`）。

### D. 工具描述加固（写进自带提示词）
- `project_edit`：追加「局部修改前置：必须先用 project_read 完整读取目标文件原文（窗口覆盖全文），否则拒绝执行」。
- `project_write`：追加「禁止用于修改已有文件的局部内容——局部修改必须用 project_edit；覆盖已有文件前必须先用 project_read 完整读取原文」。
- `manuscript`：追加「更新已有正文前必须先用 project_read 完整读取 manuscript/main.md 全文」。

## 前端（Vue3）

### E. ApprovalDialog.vue 升级
- `ApprovalItem` / 两个 composable（useMotisChat.ts:119-123、useAIAssistant.ts）payload 类型加可选 `diff` 字段。
- 有条目 diff 时：条目行改为 `+A −R` 统计徽标 + 「查看变更」按钮（替换现 160 字截断 `<pre>`，无 diff 时保留旧摘要兜底）。

### F. 新组件 ApprovalDiffModal.vue（全屏 hunk 视图）
- 复用 AboutDialog 的全屏模态样式规范（fixed overlay、z-index 2000、Escape 关闭、DESIGN.md Level 4 阴影、CSS 变量带 fallback）。
- 头部：path + `+A −R`；主体：等宽行列表——del 行红底、add 行绿底、ctx 行灰字常规、`gap_before` 渲染为「··· N 行未变 ···」折叠行（不渲染未变文本）；底部「应用 / 拒绝」直通现有 resolve 链（emit → `motis_chat_resolve_approval`）。
- i18n：`main.motisPanel.approval.*` 下补 diff 视图相关键（中英）。

## 测试与验证
- Rust 单测：read_state（区间合并/覆盖判定/指纹失效）、read_gate（未读拒绝、读后放行、新建放行、写后刷新）、approval_diff（edit 命中/歧义 None/新建全绿、上限截断）、既有工具测试随构造签名更新；`cargo test` 相应模块。
- 前端 `pnpm build` / 类型检查通过；手动走一遍 Motis 面板审批（若可运行）。

## 边界与说明
- 不改 `crates/referee`（其 EditTool/WriteTool 无 hook，全部在 app 层装饰器实现）。
- 多智能体（总督/子代理/学术助手）共享同一 ReadTracker（按绝对路径记账），符合"agent 间读过的文件互相认可"预期。
- 单文件均控制在 800 行内，read_state/read_gate/approval_diff 独立成模块。
