# Motis 子智能体超时治理与可观测性优化方案

## 问题诊断（已完成的代码探索结论）

**超时根因（3 个）**：
1. **引擎 `thinking_timeout` 默认仅 30s**（`crates/referee/referee-ai/src/session/timeout.rs:34`），Motis 主/子智能体均未覆盖 `EngineConfig`。Motis 流式回复整体被 30s 包裹（`engine/stream.rs:56`），子代理非流式每轮 LLM 被 30s select 切断 → 学术写作长生成频繁报 "turn timeout"。**这是"经常超时"的主因**。
2. **超时倒挂**：Motis 执行器给 `delegate_agent` 包 360s 工具超时，先于 600s RPC 超时切断，10 分钟注释意图失效。
3. **切断后泄漏**：被外层 timeout 切断时 delegate future 被 drop，`untrack_child` 不执行 → `Federation::inflight` 泄漏，且被切断的子会话在后台继续空跑。

**可观测性缺失**：子代理走非流式 `engine.chat()`（crates 内部），前端只见 `delegate_agent` 的"已委派"三个字，最长 10 分钟黑盒。

**约束**：不改 `crates/`（子仓库）；全部改动在 `src-tauri` + `src`；referee 后续优化写成文档。

---

## 第一部分：超时治理

### 1.1 新建 `src-tauri/src/motis_chat/timeouts.rs`（超时分层单一事实来源）
集中定义 Motis 域全部超时常量 + `motis_engine_config()` 工厂函数，模块头注释画清分层链：

| 层 | 常量 | 值 | 说明 |
|---|---|---|---|
| 审批等待 | （已在 approval.rs，300s） | 不变 | |
| 引擎单轮 LLM | `LLM_TURN_TIMEOUT` | 300s | 覆盖 thinking_timeout，主/子共用 |
| LLM HTTP 兜底 | `LLM_HTTP_TIMEOUT` | 360s | motis 域用 `build_llm_provider_with_timeout` |
| 子代理工具 | `SUBAGENT_TOOL_TIMEOUT` | 360s | 保持（审批 300s + 余量） |
| 委派 RPC | `DELEGATE_RPC_TIMEOUT_MS` | 600_000 | 从 delegate.rs 移入（10 分钟总预算） |
| Motis 工具 | `MOTIS_TOOL_TIMEOUT` | 660s | **> RPC，修复倒挂** |

`motis_engine_config()`：`EngineConfig::default()` 仅覆盖 `session.timeout.thinking_timeout = 300s`。

### 1.2 改 `motis_chat/runtime.rs`（Motis 主运行时）
- `builder.with_config(motis_engine_config())`
- executor 改 `approval_executor(MOTIS_TOOL_TIMEOUT)`（660s）
- LLM provider 改 `build_llm_provider_with_timeout(..., LLM_HTTP_TIMEOUT)`

### 1.3 改 `motis_chat/agents.rs`（子代理构建）
- `build_agent_runtime` 同样 `with_config` + `with_timeout(360s)` + `approval_executor(SUBAGENT_TOOL_TIMEOUT)`

### 1.4 改 `agent_runtime/approval.rs`
- `approval_executor()` → `approval_executor(tool_timeout: Duration)` 参数化，更新两处调用点

### 1.5 改 `motis_chat/delegate.rs` 错误信息
- `KernelError::Timeout` 特判：明确输出"委派超时（10 分钟）…"，不再与普通 RPC 失败混在一起

## 第二部分：取消传播与泄漏修复

### 2.1 改 `motis_chat/federation.rs`
- `inflight: Mutex<HashMap<Uuid, AgentId>>` 抽象为 **`DelegationTracker`**（改 `std::sync::Mutex`，临界区无 await）：`DelegationInfo { agent_id, parent_tool_call_id, task_preview, started_at }`；方法 `track / end（remove）/ lookup / snapshot`
- `Federation` 持 `Arc<DelegationTracker>`；新增 `end_child(session_id)` = untrack + interrupt 对应子会话（幂等）
- `FederationPool` 持进程级 tracker；**rebuild 前先 interrupt 旧联邦子会话**（顺带修复现存 rebuild 泄漏）

### 2.2 改 `motis_chat/delegate.rs`
- track/untrack 直调改为 **RAII guard**（`DelegationGuard`，Drop 时 `end_child`）：正常完成、外层超时切断、panic 全路径统一清理，子会话不再空跑

## 第三部分：可观测性（后端）

### 3.1 新建 `src-tauri/src/agent_runtime/observability.rs`（通用装饰器，与 approval.rs 对称）
- `trait ToolEventSink`：`on_tool_start(ctx, name, input)` / `on_tool_end(ctx, name, result, duration_ms)`
- `ObservedTool`：透明转发声明（照 ApprovalGuard 模式），execute 前后打点
- `observe_registry(&ToolRegistry, sink) -> ToolRegistry`：用 `registry.all()` 重建注册表逐个包装——**assemble.rs 与业务工具零改动**

### 3.2 改 `motis_chat/events.rs`：新增 4 个事件
- `motis:agent-started` `{ tool_call_id, agent_id, task, timeout_ms }`
- `motis:agent-tool-call` `{ tool_call_id, agent_id, id, name, input }`
- `motis:agent-tool-result` `{ tool_call_id, agent_id, id, name, result, ok, duration_ms }`（result 超 4KB 截断）
- `motis:agent-finished` `{ tool_call_id, agent_id, ok, tokens_used?, duration_ms, error? }`

### 3.3 新建 `src-tauri/src/motis_chat/agent_reporter.rs`
- `AgentReporter { emit 回调, tracker }`：实现 `ToolEventSink`（按 `ctx.session_id` 查 tracker 得父委派 `tool_call_id`/`agent_id`，精确路由，支持并行委派）；提供 `delegation_started / delegation_finished / tool_result`
- **吸收并删除现有 `ToolReporter`**（仅 3 处使用，消除冗余）；`motis:tool-result` 行为保持兼容

### 3.4 接线
- `commands.rs`：构造 emit 分发回调 + `AgentReporter`（替代 ToolReporter）
- `FederationPool::get_or_build` / `Federation::build` 增 sink 参数；`agents.rs build_agent_runtime` 增 sink 参数（registry 构建后 `observe_registry` 包装）
- `delegate.rs` 持 `AgentReporter`：委派开始发 started，成功/失败/超时各分支发 finished

## 第四部分：前端展示

### 4.1 `src/views/main/types.ts`
- `ChatMessage` 增 `agentRun?: AgentRun`；新增 `AgentRun { agentId, task, status: 'running'|'done'|'failed', startedAt, durationMs?, tokensUsed?, error?, activities: AgentActivity[] }` 与 `AgentActivity { id, name, input?, result?, ok?, durationMs?, running }`

### 4.2 `useMotisChat.ts`
- 新增 4 个 payload 接口 + `subscribeEvents` 监听 4 事件；handler 按 `tool_call_id` 挂到已有 tool_call 消息的 `agentRun` 上（活动列表增量维护）

### 4.3 `toolDescribe.ts`
- `delegate_agent` 分支：`agent_id` → `objectKey` 映射 `settings.motis.agents.*` 显示名（如"已委派 学术撰写助手"）

### 4.4 新建 `MotisAgentRun.vue`（`src/views/main/components/motis/`）
- 头部：智能体名 + 状态（运行中点点动画/完成/失败）+ 耗时 + token；活动列表：每行工具名 + 状态 + 耗时，行可展开查看参数/结果详情（样式沿用 MotisActivityGroup 设计语言）
- `MotisActivityGroup.vue`：delegate 行有 `agentRun` 时以 MotisAgentRun 作为展开详情；`index.ts` 导出

### 4.5 i18n（zh-CN / en / es 三处同步）
- `main.motisPanel.agentRun.*`（运行中/已完成/失败/耗时/tokens 等）；智能体名复用 `settings.motis.agents.*`
